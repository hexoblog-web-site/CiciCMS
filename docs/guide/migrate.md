# 搬迁到新服务器

换主机、换域名，或者从测试环境搬到正式环境。核心只有三样东西要带走：**数据库、`content/` 目录、`config.php`**。

## 搬迁前：在新服务器上准备好环境

按 [环境要求](/guide/requirement) 装好 PHP + MySQL，建一个空数据库。

## 第一步：备份数据库

老服务器后台 →「数据系统」→「立即备份」，然后点「下载」把 `.sql` 存到本地。

::: tip 顺手多备一份
用 phpMyAdmin 再导出一次也行。两条路都留一份，坏一个还有另一个。
:::

## 第二步：打包 `content/` 目录

整个 `content/` 打包下载。里面是：

| 子目录 | 里面是什么 | 能不能不要 |
| --- | --- | --- |
| `content/themes/` | 你的主题（可能改过） | 不能 |
| `content/uploads/` | 所有图片和附件 | 不能 |
| `content/plugins/` | 插件，含启用状态无关的代码 | 装了就要 |
| `content/data/backup/` | 历史备份 | 可不要，但建议带着 |
| `content/data/cache/` | 模板编译缓存 | **可以不要**，会自动重建 |
| `content/data/logs/` | 日志 | 可以不要 |

## 第三步：上传程序

新服务器上，把**同版本**的程序文件传上去（`includes/`、`admin/`、根目录 `.php`、`.htaccess`）。

::: warning 版本要一致
新环境装的程序版本最好和老站一样，或者更新。老版本程序 + 新版本数据库结构会缺字段报错。
:::

## 第四步：把 `content/` 传回去

把第二步打包的 `content/` 解压到新服务器，覆盖同名目录。

## 第五步：改 `config.php`

老站的 `config.php` 里是**老数据库**的地址和密码，新服务器一般不一样。改这四行：

```php
define('DB_HOST', '127.0.0.1');
define('DB_PORT', '3306');
define('DB_NAME', '你的库名');
define('DB_USER', '你的用户名');
define('DB_PASS', '你的密码');
```

改完权限设 644。

## 第六步：导入数据库

新服务器 phpMyAdmin（或后台「数据系统 → 数据导入」）把第一步的 `.sql` 导进去。

::: danger 导入前确认表前缀
如果新库里已经有别的站，注意别撞前缀。导入前把 `.sql` 里的前缀改成你新站要用的。
:::

## 第七步：改站点地址

如果**域名也换了**，必须改站点地址，否则生成的页面里所有链接还是老域名。

登录新后台 →「系统设置」→ 站点地址 → 改成新域名（不要以斜杠结尾）→ 保存。

然后「生成静态」→「全量生成」。这一步不能省，因为已经生成的 HTML 里写的还是老地址。

## 第八步：清缓存

删掉 `content/data/cache/tpl/` 里的文件（不是删目录）。模板缓存里存的是编译后的路径，换环境可能对不上。

程序在生成时也会自己判断，但手动清一次最省事。

## 第九步：验证

| 检查 | 期望 |
| --- | --- |
| 首页 | 正常打开，图片能显示 |
| 任意文章页 | 正文、图片、附件下载都正常 |
| 后台登录 | 能进，账号密码是老站的 |
| 系统设置 → 系统信息 | 数据库连接正常，版本对 |
| 插件 | 之前启用的还在启用状态 |
| 上传一张图 | 能传上去，前台能看到 |

## 常见问题

**图片全是红叉**
`content/uploads/` 没传全，或者目录权限不对（要 755 可读）。

**后台能进，前台 404**
没生成静态页，或者新服务器根目录没有 `index.html`。

**登录后一片空白**
`content/data/` 不可写，缓存和日志写不进去。改成 755。

**页面里的链接指向老域名**
站点地址没改，或者改了没重新生成。

**附件下载 404**
`content/uploads/files/` 没跟着搬，或者 `.htaccess` 权限被改坏。

## 搬完之后

1. 老服务器上的站先别急着关，观察一周
2. 如果换了域名，老域名做 301 跳到新域名（不然收录会掉）
3. 新服务器上再点一次「立即备份」，把这次干净的状存下来
