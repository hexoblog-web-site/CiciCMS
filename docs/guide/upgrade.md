# 升级

## 先记住一句话

**覆盖 `includes/`、`admin/`、`install/`，`content/` 和 `config.php` 不要动。**

因为程序就是这么设计的：代码在系统区，你的东西在内容区，两边互不干扰。所以升级这件事，本质上就是"换掉代码，保留数据"。

## 方式一：后台一键更新（推荐）

进「系统更新」，点「立即检查」。

流程是这样的：

1. 程序去 GitHub 取最新提交，读出里面的版本号
2. 比当前版本高（或提交号变了）就提示有新版本
3. 你点「立即更新」，它把源码包拉下来
4. **先把当前的 `includes/`、`admin/`、`index.php`、`api.php`、`.htaccess` 备份一份**
5. 逐个文件"写临时文件 → 改名覆盖"，单文件原子替换
6. 任何一步失败，整批回滚，并把原因写进日志
7. 清空模板缓存，刷新后台即可

::: tip 只用 https
更新只走 `api.github.com` 和 `codeload.github.com` 两个地址，由程序写死，不接受任何外部传入的地址。
:::

### 它会覆盖什么

| 会覆盖 | 绝不动 |
| --- | --- |
| `includes/**`、`admin/**` | `content/**`（主题、上传、插件、备份） |
| `index.php`、`api.php`、`.htaccess`、`README.md`、`LICENSE` | `config.php`（数据库配置） |
| | `install/`（装完就该删了，不请回来） |

压缩包里其他路径一律跳过；`../`、绝对路径、`content/` 下的条目都写不进来。

### 数据库结构变了怎么办

版本之间如果加了字段，程序在引导阶段会自动跑一次结构升级，不需要你手动执行 SQL。

升级记录会写进 `content/data/logs/`，形如：

```
schema: page.content_src added
schema: article.attachment added
```

看到这种日志说明升级正常做完了。**升级前请务必先备份数据库**（「数据系统 → 立即备份」），万一结构升级被打断还能恢复。

### 自动检查

不想每次手动点，可以开自动检查：

- **打开后台就检查**：页面渲染完后前端异步请求一次，到点才真联网（默认间隔 6 小时）
- **计划任务**：定时访问 `admin/cron.php?token=你的令牌`，不开后台也能查。适合常年不登录的站
- **邮件通知**：配好发信方式（`mail()` 或 SMTP），发现新版本会发信，同一个版本只发一次

配置入口都在「系统更新 → 更新设置」。

::: danger 自动更新 = 让这个仓库的代码在你服务器上执行
仓库只有你自己能推代码时，才建议打开「自动更新」。用别人的分支、或者仓库有多人协作，就只用「自动检查 + 手动点更新」。
:::

## 方式二：手动覆盖 {#manual}

在线更新走不通（主机禁了外网、GitHub 访问不了）时用这个。

1. **先备份**：后台「数据系统 → 立即备份」，再下载到本地
2. **再备份 `content/`**：整个目录打包下载（主题、图片、插件都在里面）
3. 下载新版本压缩包，解压
4. 用 FTP 把新的 `includes/`、`admin/`、`install/` 上传覆盖
5. `index.php`、`api.php`、`.htaccess`、`README.md`、`LICENSE` 也覆盖
6. **不要上传**压缩包里的 `content/` 和 `config.php`
7. 浏览器打开后台，触发一次结构升级
8. 「生成静态」点一次全量生成

## 回滚

「系统更新 → 备份与回滚」里能看到最近 3 份更新前备份，点一下就恢复。

回滚会同时删掉"更新时新增、备份里没有"的文件——避免回到旧版了还留着新版的文件，导致半新半旧。

::: warning 备份只留 3 份
更早的会自动清理。要长期留档，自己把 `content/data/backup/update/` 下载走。
:::

## 版本之间的注意事项

大部分版本升级是"覆盖就完事"，但有几个版本动过数据结构或地址规则，跨版本升级时留意：

| 从 → 到 | 要注意什么 |
| --- | --- |
| 1.4 → 1.5 | **URL 结构变了**，旧链接会 404，需要重新生成并考虑做 301 |
| 1.5 → 1.6 | 栏目增加了横幅、关键词、描述字段，需要在后台补填 |
| 1.7 → 1.8 | 默认主题改为纯 HTML 模板，旧的 PHP 模板仍可用 |
| 1.9.1 → 1.9.2 | 后台界面改版，功能位置有调整 |
| 1.9.4 → 1.9.5 | 正式定名 CiciCMS，目录名不变 |
| 1.9.5 → 2.0.0 | 引入插件系统；代码高亮从主题移到插件 |
| 2.0.0 → 2.1.x | 引入在线更新、图片上传器、数据备份体系；后续小版本多为界面调整 |

::: tip 跨大版本升级前
把整站（含 `content/`）打包留一份再动。数据库结构升级一旦中途失败，回滚代码是救不回来的，得靠数据库备份。
:::

## 升级后检查清单

1. 前台首页、栏目页、文章页各开一个，看有没有白屏/500
2. 后台「系统设置 → 系统信息」确认版本号变了
3. 「生成静态」跑一次，看错误数是不是 0
4. 看 `content/data/logs/` 最新日志有没有 error
5. 装过插件的，确认插件还在、还能用（插件目录升级不会被动）
