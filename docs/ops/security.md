# 安全加固清单

这一页分四块：**程序已经做了什么**、**你上线前必须做什么**、**哪些风险是设计上无法消除的**、**历史修复记录**（维护时别改回去）。

## 一、程序已经做了的

| # | 威胁 | 做法 |
| --- | --- | --- |
| 1 | SQL 注入 | 全部走 PDO 预处理，`ATTR_EMULATE_PREPARES = false`；表名走白名单；`LIMIT` 强制整型 |
| 2 | XSS | 输出统一 `e()` 转义；正文保存时移除 `<script>`、`<iframe>`、`on*` 事件、危险协议 |
| 3 | 链接型 XSS | `href` / `src` / `action` 逐个按浏览器规则归一化后再判断——先解 HTML5 命名实体（`&Tab;` `&NewLine;` `&colon;`），再去控制字符和空白，`java&Tab;script:` 这种拆分写法也拦 |
| 4 | CSRF | 后台所有 POST 校验一次性会话 token，用 `hash_equals()` 比较；退出登录也要求 POST |
| 5 | 暴力破解 | 同 IP 15 分钟失败 8 次锁定；密码 `password_hash()` 存储 |
| 6 | 恶意上传 | 图片用 `getimagesize()` 判真实类型；附件后缀白名单 + 明确拒绝表；随机命名；目录禁止执行 |
| 7 | SSRF | 抓图只走 http(s)，拒绝内网与保留地址，**每一跳重定向都重新校验** |
| 8 | 文件写入 | 先写临时文件再 `rename` 原子替换；路径拒绝 `..`；生成器只写 `.html/.xml/.txt/.json` |
| 9 | 并发生成 | `flock` 独占锁；状态放锁前落盘；单任务出错只记错误不中断整轮 |
| 10 | 错误泄露 | 异常统一捕获写日志；生产环境不暴露堆栈 |
| 11 | 删除误操作 | 栏目下有文章禁止删除；删文章/单页同步清旧静态文件；删图有二次核对 |
| 12 | 备份文件 | `config.php`、日志、SQL 备份由 `.htaccess` 拒绝访问 |
| 13 | 会话膨胀 | 只在实际需要时启动会话；前台静态请求不建 session 文件 |
| 14 | 自动更新 | 只走 https，地址写死；先校验包内关键文件与版本号；白名单覆盖；失败回滚；`flock` 防并发 |

## 二、上线前必须做的

按顺序做，一条都别跳：

- [ ] **删掉整个 `install/` 目录**
- [ ] `config.php` 权限改 **644**
- [ ] `includes/`、`admin/` 设 **555**，属主是 PHP 运行用户
- [ ] `content/`、根目录设 **755**
- [ ] 后台「系统设置 → 目录权限自检」跑一遍，把黄色项处理掉
- [ ] 访问 `/config.php` 确认返回 403/404，**不能下载**
- [ ] 访问 `/includes/db.php` 确认返回 403/404
- [ ] 访问 `/content/plugins/highlight/plugin.php` 确认返回 403/404
- [ ] Nginx 用户：确认写了 `content/(uploads|themes|plugins)` 那条 deny
- [ ] 管理员密码改成强密码（12 位以上，不与其他站复用）
- [ ] 「数据系统」点一次「立即备份」，下载到本地
- [ ] 站点在 CDN 后面的话，勾上「采信 X-Forwarded-For」，否则登录限速会误锁所有人

::: danger 最容易被忘的一条
**`install/` 目录。** 安装向导能重装数据库、能覆盖 `config.php`。装完不删，等于把重装权限留给了任何能访问 `/install/` 的人。

删不了（比如没权限），就在 Web 服务器上挡掉：

```nginx
location ~ ^/install/ { deny all; }
```
:::

## 三、四处设计上的固有风险

这四条不是 bug，是取舍。你得知道它们存在。

### 1. `content/plugins/` 能写也执行

**风险**：能往这里放 `plugin.php` 并"启用"的人，等于能执行任意 PHP。

**缓解**：不需要插件就删掉整个目录；只装信得过的；装前读一遍代码。

详见 [权限模型 · 例外一](/ops/permission#plugins)。

### 2. 站点根目录可写

**风险**：静态页要写进根目录，而 `index.php` 要可执行，所以根目录既是"可写"又是"可执行"。

**缓解**：生成器只允许写 `.html/.xml/.txt/.json`。彻底解法是输出目录与代码目录分离，当前版本没做。

### 3. 页脚 HTML 是原样输出的

**风险**：`site_footer` 字段按设计不转义、不过滤，等于"管理员可以在全站每个页面注入任意 JS"。

**缓解**：后台账号本身就是最高权限，能改这个字段就能做任何事。所以关键是**别把后台账号交给不可信的人**，而不是限制这个字段。

### 4. 自动更新等于远程代码执行

**风险**：仓库被攻破 / 分支被提 PR 合并 → 恶意代码会主动装到你服务器上。

**缓解**：只在"仓库只有你自己能推代码"时开自动更新；多人协作就用"自动检查 + 手动点更新"。

## 四、两次真实修复（别改回去）

这两处是审计中发现并修掉的实际问题。维护代码时如果看到相关逻辑觉得"多余"，先看完这段。

### SSRF 重定向绕过（高危）

**问题**：图片"按地址上传"和 Hexo 导入的远程抓图，原来用 `CURLOPT_FOLLOWLOCATION = true` 自动跟随重定向，但只在**第一跳之前**校验地址是不是公网。

攻击者填一个自己的公网地址 → 返回 `302 Location: http://127.0.0.1:8080` → 服务器自动跟过去。等于把一个"探测内网 / 读云元数据"的能力送到了对方手上。

**修复**：改为手动跟随，**每一跳都重新调 `cms_url_public_check()`**，最多 4 跳。

| 文件 | 改动 |
| --- | --- |
| `includes/functions.php` | 新增 `cms_url_public_check()` |
| `includes/uploader.php` | `fromUrl()` 改手动跟跳；新增 `fetchOnce()` / `absoluteUrl()` |
| `content/plugins/hexo-import/remote.php` | 同样处理（`hexo_img_fetch()` / `hexo_img_absolute()`） |

**验证**：`http://127.0.0.1:8099/...`、`http://169.254.169.254/...`、`file:///etc/passwd` 全部被拒；正常公网图片正常放行。

::: danger 如果以后要改这段
`CURLOPT_FOLLOWLOCATION` 一旦设回 `true`，这个洞立刻回来。要跟随重定向，就必须自己跟、自己校验。
:::

### 附件目录 `.htaccess` 可能导致整个目录 500

**问题**：自动生成的防护配置里裸写了 `Options -Indexes`。在限制了 `AllowOverride Options` 的主机上，这一句会让**整个附件目录报 500**，用户看到"附件全部打不开"，而且极难自查。

**修复**：每条指令都用 `<IfModule>` 包起来——不支持就跳过，而不是报错。

**为什么可以这么"松"**：真正拦住恶意附件的是**后缀白名单**（`php/phtml/phar/js/html/svg/ini` 在代码里就被拒），`.htaccess` 只是额外一层。宁可不生效，也不能让目录打不开。

## 五、还可以再加的

程序没做、但你可以自己加的：

| 措施 | 怎么做 |
| --- | --- |
| 后台 IP 白名单 | Nginx 里给 `/admin/` 加 `allow` / `deny` |
| 后台二次验证 | 没有内置 2FA。可以在 Nginx 层加 Basic Auth 做第二道门 |
| WAF | 宝塔 / 云厂商的免费 WAF 都能挡掉一批扫描 |
| 定期异地备份 | 每月把 `.sql` + `content/` 下载到本地或对象存储 |
| 日志监控 | 定时看 `content/data/logs/` 里有没有连续的报错 |
| HTTPS | 必须上。静态站上 HTTPS 成本极低（Let's Encrypt 免费） |

::: tip HTTPS 之后记得改站点地址
「系统设置」里的站点地址要从 `http://` 改成 `https://`，然后**重新生成一次**。否则静态页里还是 http 链接，浏览器会报混合内容。
:::
