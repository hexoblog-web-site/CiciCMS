# URL 与 SEO

## 地址规则

| 内容 | 地址 |
| --- | --- |
| 首页 | `/index.html`、`/page/2/index.html` |
| 文章 | `/栏目别名/5.html`（分类目录 + 文章 ID） |
| 栏目 | `/栏目别名/index.html`、`/栏目别名/page/2/index.html` |
| 单页 | `/about.html` |
| 标签 | `/tag/1a2b3c4d5e.html` |
| 归档 | `/archive.html` |
| 友链 | `/links.html` |
| 其他 | `/tags.html`、`/sitemap.xml`、`/rss.xml`、`/404.html` |

**静态文件直接躺在站点根目录**，没有任何"URL 重写 → 交给 PHP"的环节。文件存在就是 200，不存在就是 404。

除站内搜索 `/index.php?s=关键词`（要查库，无法静态化）外，前台不存在任何动态地址：旧的 `?p=` / `?cat=` / `?single=` / `?tag=` 路由已全部移除，访问一律 404。后台「预览」按钮直接指向生成好的静态页；草稿和未保存的内容在后台弹窗里渲染，不对外暴露地址。

## 文章地址为什么用 ID

`/tech/5.html` 里的 `5` 是文章 ID，不是序号。这样做的好处：

| 场景 | 用 ID | 用 slug |
| --- | --- | --- |
| 改标题 | 地址不变 ✅ | 地址不变（slug 是独立的） |
| 改英文路径 | 地址不变 ✅ | **地址变了，404** |
| 文章被删 | 地址失效 | 地址失效 |

实际上 Slug 是可选的：填了就用 slug（`/tech/hello.html`），不填就用 ID。

::: tip 想用 slug 的话
填了 slug 的地址更"好看"，但**改了就会 404**。所以：能一次定好的用 slug，可能改的用 ID。
:::

## 栏目别名不能用的名字

栏目别名直接就是站点根下的目录名，所以不能和系统目录撞：

```
admin  includes  install  content  page  tag  post  cat  api  docs  assets  uploads
```

后台保存时会直接拦下，提示"该别名为系统保留目录"。

## 地址变更对照

v2.0 之后旧地址不再兼容，**直接 404，程序不做跳转**：

| 老地址 | 新地址 |
| --- | --- |
| `/post/hello-world.html` | `/栏目别名/5.html` |
| `/cat/tech/index.html` | `/tech/index.html` |
| `/cat/tech/page/2/index.html` | `/tech/page/2/index.html` |
| `/旧别名/5.html` | `/新别名/5.html` |

::: danger 改栏目别名是唯一会大面积制造 404 的操作
已经生成的旧目录不会自动删除，但新页面都在新目录下。老链接（包括搜索引擎收录的）全部 404。

真必须改，自己在 Web 服务器上配 301：

```nginx
rewrite ^/旧别名/(.*)$ /新别名/$1 permanent;
```
:::

## 站点地图与订阅

| 文件 | 内容 | 谁在用 |
| --- | --- | --- |
| `/sitemap.xml` | 所有文章、栏目、单页的地址和更新时间 | 百度 / 谷歌站长工具 |
| `/rss.xml` | 最新文章的标题、链接、摘要 | RSS 阅读器 |

两个都在全量生成时一起产出。提交给搜索引擎：

1. 百度搜索资源平台 → 普通收录 → sitemap
2. Google Search Console → Sitemaps

::: tip 提交之后别急着看收录
新站从提交到收录通常要几天到几周。`sitemap` 只是"告诉它在哪"，不保证"马上收"。
:::

## SEO 该检查的 8 项

程序把该做的都做了，但有几项要你自己填：

| 项 | 在哪填 | 重要性 |
| --- | --- | --- |
| 站点名称 | 系统设置 | 高 |
| 站点描述 | 系统设置 | 高 |
| 栏目关键词 / 描述 | 栏目编辑 | 中 |
| 文章标题 | 写文章 | **最高** |
| 文章摘要 | 写文章（不填自动截） | 高 |
| 图片替代文字（alt） | 插图弹窗 | 中 |
| 封面图 | 写文章 | 中（列表卡片用） |
| 备案号 | 系统设置 | 合规必需 |

### 标题怎么写

程序生成的 `<title>` 规则大致是「文章标题 - 站点名」。所以：

- 文章标题里**不要再重复站点名**
- 标题控制在 30 字内，太长会被搜索结果截断
- 把关键词放前面

### 摘要为什么重要

搜索结果里显示的那两行字，通常取 `<meta description>`。程序用「手工摘要 → 自动截取正文前 120 字」的顺序。

自动截取有时候会截出半句话，**重要的文章建议手写摘要**。

## 不做伪静态，也不打算做

这点必须说清楚，免得你找半天设置：

- 整站输出真实 `.html`，服务器直接命中磁盘
- **没有** `?p=` → `.html` 的映射
- **不支持**去掉 `.html` 后缀（`/tech/5` 这种）
- **不支持** URL 自定义规则

想要伪静态 / 美化 URL，请用 Z-Blog 或 WordPress。这是设计取向，不是缺陷。

## 性能相关的几个小设置

| 设置 | 位置 | 建议 |
| --- | --- | --- |
| HTML 缓存时间 | Web 服务器 / CDN | 10 分钟 – 1 小时，太长更新看不到 |
| 图片缓存 | 已内置 30 天 | 不用改（文件名带时间戳，不会撞） |
| css/js 缓存 | 已内置 7 天 | 不用改 |
| gzip / brotli | Web 服务器 | 打开，HTML 能压到 1/4 |
| HTTP/2 或 HTTP/3 | Web 服务器 | 打开，多文件加载更快 |

## 上 CDN 要注意

静态站上 CDN 效果很好，但有一个坑：

::: warning 改了内容，CDN 还是旧的
因为 CDN 缓存了 `.html`。解决办法：

1. 把 HTML 的缓存时间设短（10 分钟）
2. 或者每次生成后在 CDN 面板手动刷一下
3. 或者用"目录刷新"刷整个站
:::

`content/uploads/` 下的图片可以长缓存（文件名唯一，永远不变）。
