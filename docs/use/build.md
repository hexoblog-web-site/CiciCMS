# 生成静态

这个页面是"把数据库里的内容变成前台能看到的 HTML"的按钮。

![生成静态](/images/admin/09-build.png)

## 三个按钮

| 按钮 | 做什么 | 什么时候用 |
| --- | --- | --- |
| **全量生成** | 按模板把所有页面重新生成一遍 | 改完模板、换主题、改站点设置之后 |
| 增量生成 | 只重建有变动的部分 | 日常小改，快 |
| 清空静态文件 | 删掉程序生成的 `.html` / `.xml` | 想彻底重来，或者目录乱了 |

::: tip 大多数时候点"全量"就对了
页面上会显示生成了多少个文件、耗时多少毫秒、有几个错误。**错误数不是 0 就往下看**。

如果「系统设置」里开了"保存后自动生成"，发文章时会自动跑一次增量，平时根本不用来这里。
:::

## 一次全量生成会产出什么

| 输出 | 路径 |
| --- | --- |
| 首页 | `/index.html` |
| 首页分页 | `/page/2/index.html`、`/page/3/index.html` … |
| 栏目页 | `/<栏目别名>/index.html` |
| 栏目分页 | `/<栏目别名>/page/2/index.html` … |
| 文章页 | `/<栏目别名>/<id或slug>.html` |
| 标签云 | `/tags.html` |
| 标签详情 | `/tag/<标签哈希>.html` |
| 归档 | `/archive.html` |
| 友链 | `/links.html` |
| 404 | `/404.html` |
| 站点地图 | `/sitemap.xml` |
| 订阅 | `/rss.xml` |

## 生成的时候发生了什么

理解这几步，出问题的时候才知道去哪查：

1. **上锁** —— 用 `flock` 独占，防止两个人同时点生成把文件写乱
2. **算清单** —— 先算出这一轮要写哪些文件（`build_plan_all()`）
3. **逐个渲染** —— 每个页面：取数据 → 套模板 → 得到 HTML
4. **逐文件写盘** —— 先写临时文件，再 `rename` 覆盖（原子替换）
5. **记清单** —— 把这次写了哪些文件记进 `content/data/static.json`
6. **清残留** —— 对比清单，删掉"上次有这次没有"的文件
7. **放锁** —— 状态落盘，解锁

### 为什么"先写临时文件再改名"

如果直接往目标文件里写，写到一半断网、断电、或者 PHP 超时，前台就会读到一个**半截的 HTML**——用户看到半截页面。

先写 `xxx.html.tmp` 再 `rename` 成 `xxx.html`，`rename` 在同一个磁盘分区上是原子操作：要么是旧文件，要么是新文件，不存在"半截"。

### 为什么只删"清单里有的"文件

`content/data/static.json` 记录了**程序自己生成过**的所有文件。清理时只删这个清单里、但这一轮没生成的文件。

这样就不会误删：

- 你手动放进去的 `.html`（比如百度/谷歌的验证文件）
- 图片、附件
- 主题文件

## 它只写这几种后缀

生成器有白名单：**只允许写 `.html`、`.xml`、`.txt`、`.json`**。

原因：静态页要写到站点根目录，而根目录必然是可写的。加个后缀白名单，至少保证"就算被利用，也写不进 `.php` 去执行"。

::: warning 但根目录可写本身仍是风险点
这是纯静态方案的固有矛盾：静态页要写进根目录，入口 `index.php` 又得可执行。彻底解法是"输出目录和代码目录分离"，见 [已知限制](/faq#limits)。
:::

## 报错了怎么办

| 提示 | 原因 | 处理 |
| --- | --- | --- |
| 写入失败 | 根目录不可写 | 改成 755，属主设为 PHP 运行用户 |
| 渲染结果为空 | 模板文件缺失或标签写错 | 看是哪个模板，用备份恢复 |
| 模板不存在 | 主题缺文件 | 补齐必备的 13 个文件，见 [模板开发](/theme/) |
| 生成到一半停住 | PHP 超时 / 内存不够 | 关掉自动生成，分批手动生成 |
| 错误数是 0 但前台没变 | 浏览器缓存 | 强制刷新 |

日志在 `content/data/logs/`，按天一个文件。

## 生成要多久

取决文章数。参考量级：

| 文章数 | 参考耗时 |
| --- | --- |
| 50 篇以内 | 1 秒内 |
| 500 篇 | 几秒 |
| 5000 篇 | 十几秒到几十秒 |

文章上千以后，建议：

1. 关掉"保存后自动生成"
2. 攒一批改动，集中点一次生成
3. 如果主机有 PHP 执行时间限制（常见 30 秒），考虑把 `max_execution_time` 调大

## 清空静态文件会删什么

只删**清单里记录的、程序生成过的**文件，不碰：

- `content/` 下任何东西
- 你的 `.php` 文件
- 手动放的验证文件
- 图片和附件

清空之后前台所有页面会 404（静态文件没了，数据库还在），不会 500。想恢复就点一次「全量生成」。
