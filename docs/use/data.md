# 数据备份与恢复

「数据系统」管四件事：备份、下载、恢复、导入。改动大动作之前，先来这里点一次备份。


## 立即备份

点一下，程序把整个数据库导成一份 `.sql` 文件，存在：

```
content/data/backup/db/备份名.sql
```

然后可以在列表里**下载**到本地，也可以直接**删除**。

::: tip 备份里有什么
所有表：配置、文章、栏目、单页、友链、附件记录、管理员。**图片和附件不在里面**——它们在 `content/uploads/`，要单独打包。

所以完整的站点备份是两份：`.sql` + `content/` 目录。
:::

## 数据恢复

从已有备份**覆盖当前数据库**。这是危险操作，所以程序设了三道关：

1. 必须选中一份已存在的备份文件
2. 必须在输入框里**手打 `RESTORE`**（大写）
3. 执行前**自动再备份一次当前数据**

第三道是关键：万一你恢复错了版本，刚才那份还在，能退回来。

### 恢复时程序做了什么

1. 先备份当前库 → `content/data/backup/db/pre-restore-xxx.sql`
2. 逐条解析 SQL 语句
3. **白名单过滤**：只放行 `SET` / `INSERT` / `REPLACE` / `TRUNCATE` / `DELETE`，且表名必须在本程序的表里
4. `TRUNCATE` 自动改写成 `DELETE`（`TRUNCATE` 不能回滚）
5. 整个过程放在**事务**里执行
6. 任何一条出错 → 全部回滚，数据库回到恢复前的样子

::: warning 为什么要有白名单
`.sql` 文件是可以被人改的。如果无脑执行，一句 `DROP DATABASE` 就够你哭。白名单保证即使备份文件被篡改，最坏情况也只是数据被覆盖，不会把库结构或别的库搞掉。
:::

## 数据导入

上传一个 `.sql` 文件并执行。和恢复的区别是：**文件来自你的电脑，不是服务器上已有的备份**。

常用于：从别的服务器搬过来、从 phpMyAdmin 导出的备份导回来。

同样会先自动备份当前数据，同样走白名单过滤和事务。

::: danger 导入前确认表前缀
如果 `.sql` 里的表名和你现在的表前缀不一致（比如人家是 `cms_`，你是 `site_`），导进去会多出一批用不上的表。导之前先看一眼文件开头。
:::

## 备份文件放哪、留多久

```
content/data/backup/
├── db/          数据库备份
├── theme/       模板每次保存前的自动备份
└── update/      在线更新前的系统区备份（只留最近 3 份）
```

::: tip 定期下载到本地
服务器上的备份只能防"改错了"。服务器本身挂了、被删了，备份也跟着没了。

建议：**每月下载一次**，本地留三份（本月、上月、上上月）。
:::

## 表前缀是什么

安装时填的那个 `cms_`。同一数据库里装多个站时必须不同。

想查当前用的什么前缀：看 `config.php` 里的 `DB_PREFIX`，或者后台「系统设置 → 系统信息」。

## 迁移到新服务器

完整流程见 [搬迁到新服务器](/guide/migrate)。简单说：备份 `.sql` + 打包 `content/` + 改 `config.php`。

## 常见问题

**备份下载下来是空的 / 只有几 KB**
数据库连不上，或者表前缀不对（导出了 0 张表）。检查「系统设置 → 系统信息」里的数据库状态。

**恢复卡住不动**
备份文件太大，超过了 PHP 的 `max_execution_time` 或 `memory_limit`。改用 phpMyAdmin 导入，或者分表处理。

**导入后前台全乱了**
多半是表前缀不一致，导进去了两套数据。删掉多余的、重新导。

**恢复后管理员登录不了**
备份里的密码是你当时设的那个。想不起来就用「忘记密码」的办法：直接改 `cms_user` 表的 `password` 字段。
