# 插件

插件能改渲染结果、接管保存动作、往后台加页面。装它就是让一段 PHP 在你服务器上跑。

## 列表页


每一行是一个插件：名称、版本、作者、说明，右侧是「启用 / 停用」按钮。声明了后台页面的，还会有「打开」。

## 启用和停用

- **启用状态存在数据库里**（`config` 表的 `plugins_active`），所以随备份一起迁移，换服务器不用重新点
- **停用即不加载**：未启用的插件根本不会被 `include`，文件留在原处，随时恢复
- 停用不会删文件、不会删数据

::: warning 启用或停用之后要重新生成
插件可能改前台输出。已经生成的 HTML 还是旧样子，去「生成静态」点一次全量。
:::

## 自带的两个插件

### 代码高亮（highlight）

给正文里的代码块着色，并加一个复制按钮。默认启用。

**它很省**：只有页面里检测到 `class="language-"` 才加载 Prism（约 43KB），没代码的页面零请求。

停用后：代码块还是深色面板 + 等宽字体，只是没颜色、没复制按钮。`class="language-xx"` 一直写在 HTML 里，所以换别的方案时内容不用改。

### Hexo 导入（hexo-import） {#hexo-import}

把旧 Hexo 站的文章批量搬进来。

**用法**

1. 在「Hexo 导入」页上传 `.md` 文件，或者整个 `_posts.zip`
2. 程序解析 front-matter（标题、日期、标签、分类）
3. **先预览**，确认字段映射对得上
4. 确认后入库

**图片怎么处理**

| 你填的地址 | 程序怎么做 |
| --- | --- |
| 完整地址 `https://old.com/a.png` | 直接下载 |
| 相对地址 `/images/a.png` | 补上你填的"图片附件完整地址"再下载 |

下载后：

- 存到 `content/uploads/images/年/月日/`
- 改名为「8 位日期 + 16 位微秒时间戳」（如 `202311111699668208727201.jpg`），后缀不变
- 正文里的地址同步换成本站地址

**失败的情况**：下载失败、超过 5MB、不是有效图片 → 保留原地址，并在结果里逐条列出来。同一批里相同的图片只下载一次。

::: tip 封面不会自动搬
front-matter 里的 `cover` 按原样入库，不做下载。要改的话先手动传进媒体信息，再改地址。
:::

## 装第三方插件

1. 把插件目录整个放到 `content/plugins/<插件ID>/`
2. 目录名必须和 `plugin.json` 里的 `id` 一致
3. 刷新「插件」页，列表里会出现
4. 点「启用」

插件目录里通常有：

```
content/plugins/<id>/
├── plugin.json    元信息（名称、版本、作者）
├── plugin.php     逻辑入口，启用时才 include
├── admin.php      可选，后台页面
└── assets/        可选，css / js / 图片
```

## 安全：必须知道的一件事

::: danger 插件 = 任意 PHP 执行权限
`content/plugins/` 是整个程序里**唯一"能写又能执行"的目录**。能往这里放一个 `plugin.php`、并且点一下"启用"的人，等于能在你的服务器上执行任意 PHP。

所以：**只装你信得过的插件。** 这和 WordPress、Z-Blog 的模型一样，不是本程序特有的问题，但你得知道。
:::

减轻风险的做法：

| 做法 | 效果 |
| --- | --- |
| 不需要插件就删掉整个 `content/plugins/` | 这一类风险直接归零 |
| 只从官方仓库/自己写的插件里装 | 去掉最大的来源 |
| 装之前看一眼 `plugin.php` 有没有可疑的 `eval`、`base64_decode`、外连地址 | 能挡掉大部分后门 |
| 定期看「插件」列表，把不用的停用 | 减少攻击面 |

## 插件和核心的边界

| 项 | 规则 |
| --- | --- |
| 函数名 | 必须加自己的前缀（如 `hexo_`）。两个插件同名函数会直接白屏 |
| 后台页面 | 只能打开**已启用**插件在 `plugin.json` 里声明的那一个文件，`..` 一律拒绝 |
| 表单提交 | 提交到 `admin_url('插件ID')`，POST 由插件自己处理，核心不抢 |
| 直接访问 | `content/plugins/.htaccess` 拒绝直接请求 `.php` 和 `.json` |

::: warning Nginx 用户注意
Nginx **不读 `.htaccess`**。必须自己加一条规则拦住 `content/plugins/*.php`，否则插件代码能被 URL 直接访问。配置见 [部署配置](/ops/deploy)。
:::
