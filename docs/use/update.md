# 系统更新

把 GitHub 仓库当分发源：比对提交 → 下载源码包 → 备份 → 覆盖程序文件。全程在后台点，不用登 FTP。


## 怎么判断有没有新版本

程序发两个请求：

1. 取跟踪分支的最新提交（`sha`、提交信息、时间）
2. 打开这个提交里的 `includes/bootstrap.php`，读出 `CMS_VERSION`

判定规则：**版本号更高**，或者**提交号和上次成功更新的不一样**。

第二个规则是为了应对"作者忘了改版本号"——只要代码动过就能识别。

结果缓存在 `content/data/update.json`，默认 6 小时查一次，不会每开一个页面就打一次网络请求。

## 三个地方能触发检查

| 方式 | 说明 | 适合 |
| --- | --- | --- |
| 打开后台任意页面 | 页面渲染完后前端异步请求一次，到点才真联网 | 默认，够用 |
| 计划任务访问 `admin/cron.php?token=...` | 不登录后台也能查 | 常年不登后台的站 |
| 「立即检查」按钮 | 强制联网，忽略间隔 | 想马上知道 |

查到新版本后，后台顶栏、仪表盘横幅、左侧菜单会同时提示；配了通知邮箱的还会发信。

## 更新流程（它到底做了什么）

1. 按 **commit 号**下载源码 zip（`codeload.github.com`），不和分支名赛跑，保证装的就是检查时看到的那份
2. 用自带的解析器读 zip（不需要 PHP 的 `ZipArchive` 扩展）
3. 先确认包里有 `includes/bootstrap.php`、`admin/index.php`、`index.php`，再读版本号，**比当前低就拒绝**
4. 把当前 `includes/`、`admin/`、`index.php`、`api.php`、`.htaccess` 备份到 `content/data/backup/update/<时间>-<版本>/`
5. 逐文件「写临时名 → rename 覆盖」，单文件原子替换
6. 任何一个文件失败 → **整批回滚**，原因写进日志
7. 清空模板编译缓存

## 它会碰哪些文件

| 会覆盖 | 绝不动 |
| --- | --- |
| `includes/**`、`admin/**` | `content/**`（主题、上传、插件、数据） |
| `index.php`、`api.php`、`.htaccess`、`README.md`、`LICENSE` | `config.php`（数据库配置） |
| | `install/`（装完就该删了，不请回来） |

压缩包里其他路径一律跳过；`../`、绝对路径、`content/` 下的条目都写不进来。

## 权限怎么处理

部署时 `includes/`、`admin/` 常设成 555（只读）。更新前程序会临时 `chmod` 成可写，结束（无论成功还是回滚）再改回原样。

如果 PHP 不是这些目录的属主、连 `chmod` 都不行，会**直接拦下**并提示你手工改权限，不会写到一半停住。

## 回滚

「备份与回滚」列出最近 3 份更新前备份，点一下就恢复。

回滚会同时删掉"更新时新增、备份里没有"的文件——避免回到旧版了还留着新版的文件，导致半新半旧。

::: warning 只留 3 份
更早的自动清理。要长期留档，自己把 `content/data/backup/update/` 下载走。
:::

## 更新设置

| 项 | 说明 | 默认 |
| --- | --- | --- |
| 仓库 | `用户名/仓库名` 形式 | 官方仓库 |
| 分支 | 跟踪哪个分支 | `main` |
| 自动检查 | 打开后台时是否检查 | 开 |
| 检查间隔 | 小时 | 6 |
| 自动更新 | 发现新版本直接装 | **关** |
| 通知邮箱 | 有新版本时发到这里 | 空 |
| 发信方式 | `mail()` 或 SMTP | `mail()` |
| cron 令牌 | 计划任务用的密钥 | 自动生成 |

::: danger 自动更新要谨慎
自动更新等于**让这个仓库的代码在你服务器上执行**。

- 仓库只有你自己能推代码 → 可以开
- 用的是别人的分支、或者仓库有多人协作 → 只开"自动检查"，手动点更新
:::

## 邮件通知怎么配

只填收件人不够，服务器得有能力把信发出去。两条路：

### PHP mail()（默认）

什么都不用填。要求主机装了 `sendmail` 或 msmtp。

- 宝塔面板默认装
- 很多虚拟主机**禁用了**
- 发不出去时后台会明确报错

### SMTP（推荐）

「更新设置 → 发信方式」选 SMTP，填服务器和账号。用的是程序自带的轻量 SMTP 客户端，不需要 Composer、不需要 `openssl` 之外的扩展。

| 邮箱 | 服务器 | 端口 | 加密 |
| --- | --- | --- | --- |
| QQ / 腾讯企业邮 | `smtp.qq.com` | 465 | SSL |
| 163 / 126 | `smtp.163.com` | 465 | SSL |
| 阿里企业邮 | `smtp.qiye.aliyun.com` | 465 | SSL |
| Gmail | `smtp.gmail.com` | 587 | STARTTLS |
| Outlook | `smtp.office365.com` | 587 | STARTTLS |

**五个要点**

1. QQ / 163 的"密码"要填**授权码**，不是登录密码。先去邮箱设置里开 SMTP 服务再生成
2. 发件邮箱多数服务商要求与登录账号一致，不确定就留空（会自动用账号）
3. 保存后点「发一封测试邮件」，失败提示会带服务器原文，比如 `535 Authentication failed`
4. 服务器要能对外连 465 / 587，部分主机会封
5. 授权码以**明文**存在 `config` 表里，数据库备份要当敏感文件保管

## 计划任务

不想打开后台也想检查更新，配一条 cron：

```
# 每 6 小时检查一次
0 */6 * * * curl -s "https://你的域名/admin/cron.php?token=你的令牌" > /dev/null
```

令牌在「更新设置」里，可以重新生成。

::: tip 令牌不对会返回什么
一律 404。不会告诉你"这里有个接口，只是你权限不够"——那等于告诉扫描器该往哪打。
:::

## 更新后检查

1. 前台首页、栏目页、文章页各开一个
2. 「系统设置 → 系统信息」确认版本号变了
3. 「生成静态」跑一次，看错误数是不是 0
4. 看 `content/data/logs/` 有没有 error
5. 插件还在不在、能不能用

## 常见问题

**检查更新一直失败**
- 主机禁了外网请求（`allow_url_fopen` / cURL 被关）
- GitHub 访问不了（国内部分机房）
- 解决办法：手动覆盖升级，见 [升级](/guide/upgrade#manual)

**更新到一半报错**
程序会自动回滚。看日志里的原因，多半是权限问题：`includes/` 属主不是 PHP 运行用户，`chmod` 失败。

**更新完白屏**
去 `content/data/logs/` 看最新一条。最常见的是主题用了新版本删掉的标签，或者 PHP 版本太低。用「回滚」退回上一版，再排查。

**回滚后还是新版本**
缓存没清。删 `content/data/cache/tpl/` 里的文件，刷新。
