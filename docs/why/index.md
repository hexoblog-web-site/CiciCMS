# 优点与解决的痛点

这一页不讲功能列表，只讲**它替你省掉了哪些麻烦**。每一条都对应一个真实场景。

## 痛点一：虚拟主机不给伪静态，链接还是一串问号

**你遇到的情况**：买了 200 块一年的虚拟主机，想装个 CMS，结果它要 `.htaccess` 重写规则，主机商说"不支持"，所有链接都是 `?id=123`。搜索引擎不爱收，用户也不好记。

**常见的解法**：换主机（花钱）、买插件（花钱）、或者忍着。

**CiciCMS 的做法**：根本不需要重写规则。文章生成出来就是真文件：

```
/index.html
/tech/index.html
/tech/12.html
/tags.html
/archive.html
```

Apache 装上就有 `DirectoryIndex index.html`，Nginx 写上 `index index.html index.php;` 就完事。**静态文件不需要任何"规则"**——它本来就是文件。

## 痛点二：升级要登 FTP 覆盖，怕把数据一起盖掉

**你遇到的情况**：新版本出来了，下载压缩包，解压，打开 FTP，一个目录一个目录对——哪些该覆盖、哪些该保留？盖错了整站数据没了。

**CiciCMS 的做法**：把"该覆盖的"和"该保留的"物理分开。

| 区 | 目录 | 升级时 |
| --- | --- | --- |
| 系统区 | `includes/` `admin/` `install/` | 整体覆盖 |
| 内容区 | `content/`（主题、图片、插件、备份） | **永不触碰** |

所以升级只有一句话：**覆盖代码目录，`content/` 和 `config.php` 不要动**。而且后台能直接点「立即更新」，连 FTP 都不用开——更新前自动备份，失败整批回滚。

## 痛点三：富文本编辑器把代码吃掉

**你遇到的情况**：写技术教程，粘贴一段 PHP，编辑器自动"帮你"把引号换成中文引号、把 `<` 转成 `&lt;`、把缩进吃掉、还塞一堆 `<span style>`。改十遍都对不上。

**CiciCMS 的做法**：编辑器就是一块裸 textarea。

- **不做任何字符替换**：你输入什么，库里存什么
- **不自动加 `<p>`**：段落由你自己控制
- **代码块用围栏**：` ```php ` 围起来，保存时转成 `<pre><code class="language-php">`
- **可选高亮**：装「代码高亮」插件就着色 + 复制按钮，不装就是深色面板

代价是：你不能像 Word 那样点按钮调字号。要排版就写 HTML——对写教程的人来说，这反而是优点。

## 痛点四：图片目录能被执行，传个马就完了

**你遇到的情况**：好多 CMS 的上传目录和程序在同一层，传个 `shell.php` 改个后缀就能执行。或者附件目录没做限制，被人传了 `.phtml`。

**CiciCMS 的做法**：三道关，而且都不依赖 Web 服务器的配置。

1. **后缀白名单**：`php / phtml / phar / js / html / svg / ini` 这些在代码里就被明确拒绝，不是靠 `.htaccess`
2. **真实类型判断**：图片用 `getimagesize()` 看文件头，不看后缀。改名的假图片过不去
3. **目录禁止执行**：上传目录自动生成 `.htaccess`，把里面所有脚本类后缀拒掉

::: warning 一处必须自己注意的
`content/plugins/` 是"能写又能执行"的目录（插件本来就要执行）。**这是全站唯一一处这样的地方**，详见 [权限模型](/ops/permission#exceptions)。不需要插件就整个删掉，风险归零。
:::

## 痛点五：传了几百张图，不知道哪些还在用

**你遇到的情况**：写了三年，`uploads/` 里躺着 800 张图，一半是改稿留下的废图。想清理，又怕删了正在用的。

**CiciCMS 的做法**：「系统清理」会逐个检查文件名有没有出现在——

文章正文、编辑源文、摘要、封面、附件、单页正文、栏目横幅、友链 Logo、系统设置的每个值、当前主题的模板文件。

只要出现过就算"在用"，不列出来。这是**故意保守**的口径：宁可少清几张，也不误删。

而且删除时还有两道保险：提交后**重新建一次引用索引**再核对（防止页面开了很久、期间刚插入的图被误判），以及只删 `content/uploads/` 内的文件，`..` 和绝对路径一律拒绝。

## 痛点六：备份靠 phpMyAdmin，恢复更是不敢碰

**你遇到的情况**：数据库导出要进 phpMyAdmin，选表、选格式、下载；恢复更麻烦，怕把现有数据盖了。

**CiciCMS 的做法**：后台「数据系统」四个按钮——

- **立即备份**：生成 `.sql`，可下载
- **数据恢复**：从已有备份覆盖，**要求手输 `RESTORE`** 才执行
- **数据导入**：上传 `.sql`
- **删除**：删旧备份

恢复和导入之前，程序都会**自动再备份一次当前数据**。也就是说，你按错了还有回头路。

恢复语句是白名单过滤的：只放行 `SET` / `INSERT` / `REPLACE` / `TRUNCATE` / `DELETE`，且限定表名，事务内执行，失败回滚。

## 痛点七：被撞库，几十次失败也没人管

**你遇到的情况**：后台登录页被人拿字典跑，跑一晚上。

**CiciCMS 的做法**：同一个 IP，15 分钟内失败 8 次就锁住，提示"失败次数过多，请 15 分钟后再试"。密码用 `password_hash()` 存，数据库里看不到明文。

::: tip 套了 CDN 的话要设置一下
站点在 CDN / 反向代理后面时，所有访客在程序看来都是同一个代理 IP，会一起被锁。到「系统设置」勾上「采信 X-Forwarded-For」即可。
:::

## 痛点八：改模板改坏了，前台全白

**你遇到的情况**：想改个样式，动了几行 HTML，保存，前台 500，也不知道改坏了哪里。

**CiciCMS 的做法**：

- 主题是纯 HTML + `{cici:}` 标签，**不写 PHP**，出错概率低得多
- 后台「模板管理」可以在线改，**每次保存前自动备份**到 `content/data/backup/theme/`
- 改坏了把备份拷回去就行
- 标签写错不会白屏，会原样输出，一眼能看出哪里没解析

## 痛点九：程序太重，装完还得装一堆东西

**你遇到的情况**：装个博客，先装 Composer，再 `composer install`，再装缓存插件，再配 Redis，再配伪静态，再配定时任务……

**CiciCMS 的做法**：零依赖。

| 通常要装 | CiciCMS |
| --- | --- |
| Composer + vendor 目录 | 不需要，`vendor/` 不存在 |
| Node / npm 构建 | 不需要，没有构建步骤 |
| Redis / Memcached | 不需要，静态页不用缓存 |
| 伪静态规则 | 不需要 |
| 定时任务 | 可选（只用于自动检查更新） |
| CDN / 对象存储 | 可选 |
| 前端框架 | 不需要，原生 HTML/CSS/JS |
| 图标库 | 不需要，图标是手写 SVG |
| 字体包 | 不需要，用系统字体栈 |

部署只需要两个东西：**PHP 和 MySQL**。

## 优点汇总

### 性能

- 访客访问的是静态文件，数据库不参与，人再多也不慢
- 能整站上 CDN，回源压力接近零
- 数据库挂了前台照常开，只有后台进不去
- 代码高亮插件**检测到页面里有代码块才加载**，没代码的页面零请求

### 部署

- 虚拟主机就能跑，不需要 root
- 安装向导 5 分钟走完，全程点鼠标
- 搬迁只要带走三样：数据库、`content/`、`config.php`

### 维护

- 在线更新，不用登 FTP
- 更新前自动备份，失败整批回滚，能一键回到上一版
- 数据结构升级自动做，不用手动跑 SQL
- 系统清理防止废图堆积
- 目录权限自检，一眼看出哪里没设对

### 安全

- 全部 SQL 走 PDO 预处理（`ATTR_EMULATE_PREPARES=false`）
- 后台所有 POST 校验 CSRF，用 `hash_equals()` 防时序攻击
- 输出统一 `e()` 转义；正文保存时移除 `<script>`、`on*` 事件、危险协议
- 链接类属性按浏览器规则归一化后再判断，`java&Tab;script:` 这种拆分写法也拦得住
- 写盘先写临时文件再 `rename`，原子替换，不会读到半个文件
- 登录限速、密码哈希、上传白名单、目录禁止执行

### 写作体验

- 纯 textarea，粘贴什么就是什么
- 代码围栏自动转面板
- 封面、附件都能直接上传，地址自动填
- 保存即自动重建静态页（可关）

### 内容迁移

- 内置 Hexo 导入：传 `.md` 或 `.zip`，先预览再入库，图片一起搬回本地
- 数据库是标准 MySQL 表，想走随时能走
- 备份是标准 `.sql`，phpMyAdmin 直接能导

## 诚实说几个取舍

优点说完了，代价也得说清楚：

| 取舍 | 说明 |
| --- | --- |
| 改完要生成 | 静态的必然。开了自动生成就感觉不到 |
| 没有评论 / 会员 | 单管理员模型，需要的话得自己扩展 |
| 栏目只有一级 | 表里留了 `parent_id`，但后台没做多级管理界面 |
| 搜索是动态的 | `/index.php?s=关键词`，静态站想纯静态搜索得接第三方 |
| 正文不是完整 Markdown | 支持代码围栏，但标题、表格、列表还是写 HTML |
| 根目录必须可写 | 静态页要写进去，这是纯静态方案的固有矛盾（见 [已知限制](/faq#limits)） |
